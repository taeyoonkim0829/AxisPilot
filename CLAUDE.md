# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Language

Talk to the user in Korean, always: every reply, question, progress note, summary and report (also the reports agents write, e.g. `reports/brackets/`). Code, comments, identifiers, commit messages and this file stay in English; UI text follows `src/i18n/` (Korean source strings with English in `en.ts`).

## Project status

AxisPilot (formerly Axis Selection) is a browser-only web app (React 19 + TypeScript + Vite, no backend; product data bundled as JSON). UI text is Korean with an English toggle (see `src/i18n/`). Mounting kits are matched by interface code and checked against their data sheet values (transferable torque, max. speed, inertia, no-load torque); the motor step's verdict includes the recommended kit's.

## Domain

The app sizes and selects a Festo Cartesian (linear) axis, plus the matching motor mounting kit and motor, from user-entered transport conditions.

**Inputs:** stroke, velocity, acceleration, jerk, payload mass, payload center of gravity (x/y/z offsets), mounting orientation — floor (horizontal), wall (horizontal, side-mounted), or vertical.

**Selection outputs, in order (each step depends on the previous):**
1. **Axis** — Festo ELGT, ELGD, EGC (incl. EGC-HD, ELGD-WD), ESBF (electric cylinder, ball screw)
2. **Motor** — Festo, Siemens, Mitsubishi; for Festo, Siemens and Mitsubishi motors also the servo drive (CMMT, S210/V90, MR-J5/MR-J4), motor cables and braking resistor
3. **Gearbox** — optional (direct drive or a compatible gearbox)
4. **Motor–axis mounting kit** — Festo, matched to the gearbox output when one is used
5. **Combination drawing** — the manufacturers' CAD models (STEP) assembled: 3D preview, STEP and DXF export

## Product data

The JSON files in `data/` are the source of truth and are edited by hand. The original Excel workbooks (Festo E-Drive selection Ver15.04, Motor Kit_Selection) and their export script are retired. Layout: one file per maker and product family, `data/<kind>/<maker>/<family>.json` with kind = `axes`, `motors`, `gearboxes`, `kits`, `drives`, `brakingResistors`, `cables`, `shafts` or `adapters` (gantry kits). Each file is `{ "items": [...] }`. `src/data/index.ts` loads every file with `import.meta.glob`, so new files need no code change. Discontinued families are left out there with `!` glob patterns while their files stay in `data/`: Mitsubishi HF-KP/HF-SP and Apex PA. **`data/README.md` lists every field with its unit.** Keep it in sync when adding fields.

Data gotchas:
- Units are mm, kg, N, Nm, kg·cm², m/s, rpm (per field in `data/README.md`).
- Motor `inertia` includes the brake for brake models; `inertiaWithoutBrake` excludes it.
- Gearbox `ratio` is i (5 = 5:1).
- Axis `speedLimitStroke`: for spindle axes, max speed is derated above this stroke.
- Mounting kits fit by **interface code**, not by part name. A kit matches when `axisCode` = the axis's `interfaceCode` and `motorCode` = the motor's `interfaceCode`, or the gearbox's (output side) when a gearbox sits in between. Part names often differ from the codes (`EAMM-A-T42-60P` is listed for `60PA`), and one kit has one item per code pair.
- `interfaceCode` is `null` for products whose code is unknown: about 290 motors (e.g. EMMS-AS, EMME, HK-*, HG-JR) and the Apex PA/AE gearboxes and AB/ABR sizes beyond the original Excel (AB142 and up, AB060A/AB090A, ABR). Fill it in from Festo's kit documentation; don't guess from similar products. Exception, confirmed by the user: HF-KP shares HG-KR's mounting dimensions and HF-SP shares HG-SR's, so HF-KP/HF-SP take the HG codes, and Apex `driveCode` comes from its `compatibleMotors` (all HF-KP/HF-SP). For the same reason Apex `compatibleMotors` lists the HG-KR/HG-SR code next to each HF code (`KP13` + `KR13`, `SP102` + `SR102`), so HG-KR/HG-SR get the same gearboxes.
- Festo motors come from the Festo data sheets (folder `Drive & Motor`): EMMT-AS/EC, EMMB-AS, EMMH-AS, EMMT-ST, EMMB-ST (closed loop) and EMMS-ST (open loop). EMCA, EMME-AS and EMMS-AS were removed (no data sheet). Families are series names (`EMMT-AS`, `EMMT-ST` …). Steppers carry `torqueCurve` (48 V); `controller` names the drive range. `orderCode`/`partNumber` are the base configuration's order type and part number (single-turn encoder, smooth shaft); the report's selection table lists them, plus the drive, cables and external braking resistor.
- Siemens drive packages: `data/drives/Siemens/S210.json` (1FK2) and `V90.json` (1FL6) with `motors` = the manuals' combination tables, cables in `data/cables/Siemens/MOTION-CONNECT.json`. 1FK2 models rated for both supplies have a second item `<model> (230V)` (S210 1AC table, or 3AC at 240 V for the sizes the 1AC table leaves out, `controller: S210-3AC`). Every motor carries `voltage` (200/230, 400 or 48) for the supply filter; Mitsubishi HG/HF from the model naming. Siemens drive fields the manuals do not give are `null` (peak power, cable limit on V90, resistor voltage, external resistor max).
- Mitsubishi drive packages: `data/drives/Mitsubishi/MR-J5.json` (HK, the -A general-purpose amplifier stands for -G/-B: same power ratings) and `MR-J4.json` (HG) with `motors` = the standard-torque combinations of the manuals (torque-increased pairs left out, except HK-ST903W / 9034W (400V), which have no other), cables in `data/cables/Mitsubishi/MR-J5.json` / `MR-J4.json` (high flex -H; power cables of the larger motors are user-made on the connector set, `configurable` with the set as part number). The manuals give no amplifier max. current, overload time or resistor pulse rating: `peakCurrent`, `peakDuration`, `pulsePower`, `pulseEnergy` are `null` (not checked). Motor `allowableInertiaRatio` is the manual's value up to the rated speed (the lower value above it is not modelled).
- CAD models sit in `data/<kind>/<maker>/Drawings/…/<partNumber>_<model>.stp` with a JSON of mating frames next to each (format in `data/README.md`). So far: every standard stroke of every Festo axis type (ELGT-TB-…-CS: Festo Korea's Creo exports, one per standard stroke, 25–33 MB each, no `stretch` since the profile is not a part of its own; the drive head is taken like EGC-HD-TB's, not confirmed by Festo), the EMGA gearboxes (straight and -A- angle) and the priority-1 kits (standard EAMM-A/-U between a Festo axis and a Festo motor or EMGA), all with frame JSONs generated by `scripts/festo-cad/frames.mjs` (axis JSONs also carry `profile`, the profile's mounting face, `frames.mjs --profile`) (EAMM-A-T46-60P and EAMM-U-87-T46-60P-114 are the hand-made originals, which the script reproduces; parallel kits put the motor below the axis); the gantry kits in `data/adapters` (frames from `scripts/festo-cad/adapter-frames.mjs`; the custom cross beams and the EGC angle brackets / adapter plates in `data/adapters/Custom` are this repository's cadgen models from `cad/brackets/`, with STEP, frame JSON and PDF shop drawing, see `data/README.md`; EGC-TB/BS-KF axis JSONs carry `slide.pattern`, the slide hole pattern centre beside the slide centre, where the gantry drawing seats a kit); the Festo motors in the data (no JSON needed: flange at z = 0, shaft +z, connector +y; EMMS-ST-28 models a lead reaching z = +156); Mitsubishi's motor files (every 200 V HG-KR/HG-SR/HG-JR (of the 400 V class only HG-JR3534/5034), HK-MT (not the …VW) and HK-RT motor in the data has one, HK-KT/ST except the 400 V class (…4W) and a few sizes; file names like `hg-kr13b_.stp`, matched without the data's `(200V)` suffix; flange at z = 0 like Festo, so no JSON); Siemens 1FK2 / 1FL6 files (`motors/Siemens/Drawings/<family>/<order number>/…_3D_en.STP`, shaft −y, connector +z, each with a flange JSON from `scripts/festo-cad/motor-frames.mjs`; matched by `siemensVariant`: 1FK2 models are the order number up to the brake digit, 1FL6 plain-shaft models take the featherkey file). Only STEP is committed (the build writes them gzipped under their own names, `vite.config.ts` `gzipDrawings`, keeping the GitHub Pages site under 1 GB; `cad/stepText.ts` unpacks them after the fetch, the dev server serves them raw); the makers' DWG/DXF/IGES/ZIP downloads (and the PDF/XLS/CSV sheets that come with Siemens's) are git-ignored. The CADENAS files are CC BY-ND 4.0: the assembly copies them unchanged, but the axis length change edits the profile geometry.
- SA kits (`special: true`, custom-made in Korea) took their codes from the kit name, so they may not match standard motor codes. Three have axis codes that exist on no axis (`T46-60` ×2, `T42-80`).
- Kit transferable torque, inertia, max speed, mass, ratio (1) and the parallel kits' no-load torque come from the EAMM-A / EAMM-U data sheet tables; `dataSource` names the current-generation row (…-G2) when the kit's own name is not listed. Kits missing from the data sheets (the BF…/EB…/GD… inspection-window kits, older K… kits) keep `null`, and so do `efficiency` and `length`.

## Calculation reference (from the Excel)

The original E-Drive workbook (now retired) had four calc sheets — `BS_Horizontal`, `BS_Vertical`, `Belt_Horizontal`, `Belt_Vertical` — whose formulas the app's selection logic should reproduce. Wall mounting uses the "Horizontal [Sideways]" load case of the horizontal sheets. Key formulas (g = 9.81, η = drive efficiency — default 0.9 spindle / 0.8 belt, μ = friction — 0.05 spindle / 0.1 belt):

- **Travel per motor rev** dS: spindle `pitch / i`; belt `π · pulleyDiameter / i`.
- **Motion profile** (Excel is trapezoidal; jerk is a new input not in the Excel): `Tsa = v/a`, accel distance `v·Tsa/2`, constant-velocity distance `stroke − 2·accelDist`, cycle `tf = travel time + dwell`.
- **Inertia at motor** `JL = J_gear + J_brake + WL·(dS/(20π))² + (J_coupling + J_other + J_screw or z·J_pulley)/i²`, where WL = payload + slide mass; `J_screw = π·0.0078·(L/10)/32·(D/10)⁴` with L = stroke + 100.
- **Load torque** horizontal `TL = (Fc + μ(WL·g + FG))·dS / (2000π·η)`; vertical splits into unbalance `TU` and friction `TF` torques with separate up/down cases.
- **Accel/decel torque** `TMa = (JL/η + JM)·N0 / (9.55e4·Tsa) + TL`, `TMd = −(JL·η + JM)·N0 / (9.55e4·Tsa) + TL`; RMS torque over the cycle; check peak vs motor peak torque, RMS vs rated torque, `JL/JM` vs the motor's allowable inertia ratio, required speed vs rated speed.
- **Regeneration** `Pr = (ηm·Em − Ec)/tf` vs the motor's `regenPower`.
- **Festo criteria**: required force `Fc + FG + WL·a + μ·WL·g` (vertical: `+ WL·g`) ≤ `maxFeedForce`; required axis torque `F·dS/(2π·η·1000) + noLoadTorque` ≤ `maxDrivingTorque`; Festo inertia `J0 + JH·stroke/1000 + JL·payload + J_gear`.
- **Guide load**: forces/moments from payload COG offsets and inertial force `m·a`, combined `fv = Σ|F_i/F_max,i| < 1`; guide life `(1/fv)³ · 5000 km`.
- **Deflection**: simply supported beam with point load + self-weight using `Iy`/`Iz`, E = 70000 N/mm², vs `allowableDeflection`.
- **Ball screw life** (`Ball Screw 수명계산`): `L = (Ca / (fw·Fa))³ · 10⁶` rev, with load factor fw by speed (≤0.25 m/s: 1.2, ≤1: 1.5, ≤2: 2, >2: 3.5).

### Where the app deviates from the Excel (intentional)

- Load inertia uses Festo's catalog values `J0 + JH·stroke + JL·payload` instead of computing screw/pulley inertia from dimensions.
- Gearbox inertia and brake inertia are counted once on the motor side. The Excel adds them twice.
- Vertical guide moments use `m·(g + a)` once. The Excel's Mz counts gravity twice.
- Resistance is `Fc + μ·m·g + FG`. The Excel formula applies μ to FG as well.
- Jerk gives an S-curve profile. Torques, RMS and regeneration energy are integrated numerically over a full cycle: forward, back, then one dwell (the Excel has a dwell after each move).

## Architecture

- Two screens, switched at the top of the input column (`ModeSwitch`, above 사용 조건; `#gantry` in the address = gantry): 단축 선정 (one axis, with its parallel arrangement) and 조합축 선정 (XYZ / YZ / XY combination). `src/selection.ts` holds one axis's selection chain (`computeSelection(req, settings, picks)`: axis list, the picked or recommended axis, motors, gearbox options, kits), used by both screens; `ui/AxisSteps.tsx` renders the motion profile and steps 1–5 for one axis; `ui/useReportExport.ts` is the PDF export flow.
- `src/data/` loads every JSON file with `import.meta.glob` (`index.ts`) and defines the types (`types.ts`). `gearboxesFor` matches Apex compatibility codes (e.g. `KP053`) against motor model names (not followed by another digit: `SR52` is not HG-SR524). Festo EMGA items list motor series (`EMMT-AS-60`, …) from the ordering table in Festo's documentation, so they match the same way.
- `src/calc/` contains the pure, unit-tested selection logic in SI units. Inputs use mm and kg·cm², converted at the boundaries.
  - `motionProfile.ts`: move profiles are lists of `Phase`s with linearly varying acceleration (`Phase.load` = process force from pressing). `samplePhases` turns them into weighted samples (midpoint rule, plus zero-weight boundary points so peaks are exact).
  - `axisSelection.ts`: `evaluateAxis` builds the cycle (`cyclePhases`: forward, return, one dwell; `forwardPhases`/`backPhases` are one move with the dwell at its end, for the chart views) and computes per-sample torque at the axis drive shaft (`AxisSample.torque`, efficiency not applied). It runs the motor-independent checks (stroke, speed, accel, Fx, drive torque, guide fv, deflection) and life info. `mountingPosition: 'horizontal'` (ELGT-TB) adds `설치 방향`: vertical fails, wall warns. Ball screw axes take the speed limit from `speedCurve` (data sheet speed-stroke curve) at the built stroke, with a note when it is below `maxSpeed`; the old `스트로크별 속도 한계` warning (Excel `speedLimitStroke`) only remains for axes without a curve. ELGD-BS limits `이송력 Fx` the same way with `feedForceCurve` (screw buckling, force towards the motor); since the motor side is unknown, the larger force of both directions is checked. Ball screw life is the smaller of the load-based life and, for ESBF-BS, `maxSwitchingCycles` (10 million round trips) × 2 × stroke; under 5000 km (`SCREW_LIFE_MIN_KM`) the info item has `alert` and is shown in red, and a `볼스크류 수명` check warns. Electric cylinders (ESBF) carry data sheet curves instead of guide data: `압축력 (좌굴)` checks the largest pushing force (forward = rod extending) against `pressureForceCurve` at the stroke (`fail`), and `로드 횡하중 Fq` replaces the guide fv check, comparing the payload's lateral force with `rodLateralForceCurve` (`fail`). The ESBF 외부 가이드 사용 switch in the axis step (`Settings.externalGuide`) skips that check because the external guide carries the payload; its friction can go in 가이드 저항 FG. The moving mass adds `slideMassPer10mm` per stroke. Pressing mode (`Requirements.press`, 프레싱 in the 어플리케이션 선택 box between the input box and 상세 설정; default 일반; choosing 프레싱 sets the axis filters to 볼스크류 + ESBF and turns 외부 가이드 사용 on for floor/wall and off for vertical, also when the mounting changes while pressing; back to 일반 restores the default filters): the forward half becomes approach (stroke − press distance at the set velocity) → press move (press distance at press speed) → hold (standstill, `dir` +1), and the press move and hold carry the press force as `Phase.load`; the return has none. On a vertical axis the forward move goes up, or down when pressing top-down (`press.direction`, 압착 방향, shown for vertical + pressing; `verticalForward`): the weight then helps the press and the return lifts it. Chart, report and `moveLabel` name the moves 상승/하강 accordingly. So Fx, buckling, drive torque, peak/RMS torque and screw life see the press force only where it acts. `evaluateDrive` adds `가압 구간 토크` (torque of the press move at constant speed and the hold, forward efficiency applied, vs rated torque; warns like the constant-velocity torque, fails when conservative; shown whenever pressing), and `등속 구간 토크` covers only the travel moves (approach and return), leaving the press force out. Parallel arrangement (`Requirements.parallel`, 축 구성 box below 어플리케이션 선택; `parallelLayout`): members side by side along slide y, centred on y = 0: COG y is measured from the centre of the arrangement (two axes or axis + one guide at ∓spacing/2, the first axis at −; axis + two LM guides at −spacing, 0, +spacing, the axis in the middle or at −spacing), so a centred payload splits 50/50; the drawing is built from the first axis (`axisCog` shifts the COG to it). `twinMotor` (2축 · 모터 동기): each axis carries its lever-rule share of the payload (`layout.share`, the more loaded axis is checked; Fc, FG and the press force scale with it) and has its own motor, kit and drive (report quantity 2). `twinShaft` (2축 · 기구 동기): axis checks per axis likewise, but `samples`/`driveAt`/`inertia` are the motor train — both axes (inertia, no-load torque ×2), the whole payload and the connecting shaft; `구동 토크 (연결축 포함)` warns when the total exceeds the axis drive torque. The shaft is the Festo KSK that fits the axis (`shaftSelection.ts`, `data/shafts/Festo/KSK.json`, EGC-TB-KF and ELGD-TB(-WD)): nominal length LN = spacing − `Axis.driveWidth`, inertia J0 + JL·LN (`AxisEvaluation.shaft`), and fail checks `연결축 공칭 길이 LN` (order range), `연결축 전달 토크` (second axis's torque ÷ η + the shaft's acceleration torque vs rated torque) and `연결축 최대 회전수` (speed curve at LN); other axes take the entered `shaftInertia` with a `연결축 (KSK)` warning. The report's selection table lists the KSK. `guides` (축 + LM 가이드, 1 guide, or 2 with the axis in the middle or at the edge, `guideAxisEdge`): the axis drives the payload plus `guideMass` per guide. `memberLoads` spreads the guide loads over the members (rigid plate): the rolling moment becomes normal forces across the members (no Mx), My/Mz and in-plane forces are shared equally; with two axes the drives take the yaw of forces in the travel direction. Deflection uses the axis member's share; the LM guide loads (largest per guide) are info items for choosing the guides. The combination drawing adds the second axis of a twin arrangement at +spacing (`buildCombo`'s `twin`: with its own kit, gearbox and motor under motor sync; under shaft sync the KSK drawing (`data/shafts/Festo/Drawings`, `shaftDrawingFor`) lengthened to LN (left out with a warning when LN is below the KSK's minimum, `shaftTooShort`: its model is drawn at that length) joins the first axis's free shaft end, its cover cap removed (`withoutCaps`), to the second axis (EGC-TB-KF: the first's mirror image, `mirrorAxis`, as under motor sync), and the motor goes to the shaft end away from the second axis (`shaftDrivePosition`; step 5 offers only those motor positions, the report follows); LM guides are not drawn).
 `selectAxes` filters and sorts by status, then axis mass. `axisOrder` gives the model and order number for the required stroke (ESBF, ELGT, ELGD, EGC; ELGT-TB is a customer solution `ELGT-TB-…-CS` with a part number for every stroke and no modular system): it rounds up to the next standard stroke (`strokePartNumbers`) unless a fixed modular stroke is shorter (ELGT-BS-120/160: standard from 300, fixed from 100), otherwise it orders by `moduleNumber` (modular product system) with the stroke rounded up to a whole mm within `moduleStrokes.variable`, or to the next `moduleStrokes.fixed` stroke above it (ELGT-BS has fixed strokes only); the … in `typeCode` (or the ESBF `model`) takes the stroke, and mass/inertia use the ordered stroke. `AxisEvaluation.order` is what the UI and report show as the axis model. Order options (`axisOptions`, the 추가 슬라이드 / 벨트 row under the axis step filters, `Settings.additionalSlide` and `beltMaterial`, shown while ELGD or EGC belt axes are listed): an additional slide (`Axis.additionalSlide`, ZL/ZR or KL/KR, both = KL + KR on EGC only: other ELGD-TB axes then leave the list, axes without the option stay as they are) is added to the type code before the belt code, orders by module number with the stroke lengthened by slide length + gap, adds its mass to the moving mass and axis mass and its JW to the inertia, and the payload plate spans the slides: `slideGroupLoads` turns My/Mz into opposing forces across the slides (spacing = half of both slide lengths + gap) and checks the most loaded slide; the drawing keeps one slide (noted in step 5). The belt material (`Axis.beltMaterials`) changes the no-load torque (`AxisEvaluation.noLoadTorque`; no data → the axis value with a note on 구동 토크).
  - `motorSelection.ts`: `evaluateDrive` reuses the axis samples. It applies gearbox ratio and efficiency (÷η when motoring, ×η when regenerating), adds rotor/gearbox/coupling inertia, and checks peak/RMS torque, speed, inertia ratio and regeneration, plus gearbox max output torque and max input speed (`maxInputSpeed`, EMGA and Apex AB/ABR; others skip with a note). Apex `maxTorque` is T2B = 1.8 × T2N. Steppers (`torqueCurve`) add `토크-회전수 선도`: the motor torque at each sample vs the 48 V curve at that speed (open loop ÷ `OPEN_LOOP_SAFETY` 1.5). `selectMotors` filters by maker, power supply (`Settings.supplies`, one of the AC 380–480 V / AC 200–240 V / DC 24/48 V buttons after the maker filter, set by the maker when it is picked: Festo and Siemens AC 380–480 V, Mitsubishi AC 200–240 V (`makerSupply` in MotorStep); `motorSupply`: `Motor.voltage`, else the drive range in `controller`; motors without either are always listed), family and brake, and keeps one option per motor (its optional `attachKit` hook, given `attachParts` in selection.ts = `kitSelection.attachKit` then `controllerSelection.attachController`, adds the kit and the Festo drive package before the gearbox choice and the sort), by `Settings.useGearbox` (the 감속기 미사용 / 감속기 사용 switch in the motor step, between the maker and brake filters): off checks direct drive only; on checks each motor with its compatible gearboxes (`gearboxOptionsFor`, lowest ratio first) and keeps the lowest passing ratio (the lowest ratio when none passes), dropping motors without gearbox data.
  - `kitSelection.ts`: `findKits` matches kits by interface code (gearbox output code when a gearbox is used). SA kits are returned separately as reference. `evaluateKit` checks a kit for the selected axis and drive: `키트 전달 토크` (axis input torque + the kit's own inertia and no-load torque vs `transmissibleTorque`, fail) and `키트 최대 회전수` (axis shaft speed, fail); `모터 최대 토크 (키트 기준)` shows 주의 in the details when the motor (× gearbox) can exceed the kit torque (set a drive torque limit), but it is advice only: it stays out of the kit verdict (`MOTOR_MAX_LABEL`) and the rail's headline; and, with kit data, `최대 토크` / `실효 토크` / `관성비 (키트 포함)` re-run the motor checks with the kit's inertia and no-load torque (without a gearbox the kit inertia replaces `couplingInertia`); with a parallel kit, `이송력 Fx (병렬 키트)` checks the axis peak force against the ELGD's `maxFeedForceParallel` (fail). Axis data are kit-neutral: the old Excel `_parallel kit` axis entries were dropped, their only difference (lower Fx) lives in `maxFeedForceParallel`. Missing kit data gives `ok` with `키트 데이터 없음 — 확인 필요`. `attachKit` checks every matching kit for a drive (`DriveEvaluation.kits`), recommends the first one that does not fail, preferring kits with data sheet values (`kit`), keeps the drive's own verdict in `driveStatus` and folds the kit's into `status` (`warn` when no kit fits); App uses it for the motor list and the gearbox options, so the motor, gearbox and kit steps agree.
